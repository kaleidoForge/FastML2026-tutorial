Case Study: Pile-up rejection

The original signals were acquired using a Scionix 38B38/SPII-E3-X2 scintillation detector, which features a 38 × 38 mm NaI(Tl) crystal coupled to a Silicon Photomultiplier (SiPM) readout module. The analog signals were digitized using a 14-bit Analog-to-Digital Converter (ADC) operating at a sampling frequency of 50 MHz.

To capture a diverse set of events, the original experimental setup involved continuous four-hour data acquisition under natural background radiation and controlled exposure to radioactive sources (22Na, 60Co, and specifically two 137Cs sources positioned to maximize the probability of high-count-rate temporal overlap).

In this project, the main objective is to discriminate between two classes: regular (left) and pile-up (right) pulses. Both the signals are shown in the following figure.

Data Treatment & HLS Interfaces

Before sending data to the FPGA, it is essential to align the software representations with the hardware constraints. The neural network inputs undergo a per-sample normalization within the [-1, 1] range, and are subsequently cast into a fixed-point integer format (e.g., ap_fixed<16,6>) using a specific scaling factor (e.g., 1024.0 for 10 fractional bits).

Fixed-Point Conversion Python Snippet: 
# "per-sample" normalization - range [-1, 1]
min_vals = np.min(x_pulses, axis=1, keepdims=True)
max_vals = np.max(x_pulses, axis=1, keepdims=True)
value_range = max_vals - min_vals
value_range[value_range == 0] = 1e-7 
x_normalized = 2.0 * (x_pulses - min_vals) / value_range - 1.0

# Fixed point conversion (frac_bits = 10)
# Multiply, round to the nearest integer, and cast to int32
x_fixed_point = np.round(x_normalized * 1024.0).astype(np.int32)

On the hardware side, KalEdge automatically configures the HLS C++ generated core to use standard AXI4-Stream interfaces for high-throughput data transfer (DMA) and an AXI4-Lite interface for control signals.

HLS Interface Directives: 
void myproject_auto_accel(
    hls::stream<axis_t> &s_axis_in,
    hls::stream<axis_t> &s_axis_out
) {
#pragma HLS INTERFACE axis      port=s_axis_in
#pragma HLS INTERFACE axis      port=s_axis_out
#pragma HLS INTERFACE s_axilite port=return bundle=CTRL
}

Understanding the HLS Pragmas

  • #pragma HLS INTERFACE axis: This directive tells Vivado HLS to implement the input (s_axis_in) and output (s_axis_out) ports using the AXI4-Stream protocol. This is crucial for high-speed, direct memory access (DMA) transfers, allowing the FPGA to process thousands of pulses continuously without CPU intervention.
  • #pragma HLS INTERFACE s_axilite port=return bundle=CTRL: This implements an AXI4-Lite memory-mapped interface grouped under the CTRL bundle. It exposes control registers to the ARM processor (via PYNQ), allowing the Python environment to start, stop, and monitor the IP Core's execution status (like `ap_start`, `ap_done`, and `ap_ready`).
